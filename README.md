# SE2-group-12-Mountain-Hut
Mountain Hut Management System – A web application developed for the Software Engineering II course at Politecnico di Torino (2026/2027). Designed to support mountain hut operations by coordinating hikers, reservations, staff activities, and resource management through a centralized platform.

# Docker Deployment

The Mountain Hut application is distributed through Docker.

The published application image contains:

- the React frontend;
- the Node.js / Express backend;
- SQLite support;
- the database migrations.

The deployment also uses **Mailpit** as a separate Docker service for testing email delivery.

### Requirements

The only requirement is a Docker installation supporting Docker Compose, such as Docker Desktop.

Node.js, npm and SQLite do not need to be installed locally.

### Docker image

The Mountain Hut application image is available on Docker Hub:

```text
s293687/se2-group-12-mountain-hut:latest
```

Docker Hub:

```text
https://hub.docker.com/r/s293687/se2-group-12-mountain-hut
```

## Running the application

### 1. Clone the repository

```bash
git clone <repository-url>
cd SE2-group-12-Mountain-Hut
```

### 2. Start the complete deployment

From the repository root, run:

```bash
docker compose -f backend/docker-compose.yml up -d
```

Docker Compose will automatically start:

- the Mountain Hut application container;
- the Mailpit container.

If the Mountain Hut image is not already available locally, Docker will automatically download it from Docker Hub.

The application container automatically runs the database migrations before starting the server.

### 3. Load the demo data

Once the containers are running, populate the database with the demo data:

```bash
docker compose -f backend/docker-compose.yml exec app npm run db:seed
```

The seed creates the demo users and the data required to test the application.

### 4. Open the application

The Mountain Hut web application is available at:

```text
http://localhost:3000
```

## Email testing with Mailpit

The deployment includes Mailpit as a separate Docker service.

Mailpit acts as a local SMTP server and captures the emails generated by Mountain Hut instead of sending them to real external addresses.

This makes it possible to test features such as booking confirmation emails directly from the deployed application.

Mailpit is started automatically by:

```bash
docker compose -f backend/docker-compose.yml up -d
```

No additional Mailpit setup is required.

The Mountain Hut container communicates with Mailpit through the Docker network using:

```text
mailpit:1025
```

To inspect the generated emails, open the Mailpit web interface:

```text
http://localhost:8025
```

For example, after creating a booking that generates a confirmation email:

1. perform the booking from `http://localhost:3000`;
2. open `http://localhost:8025`;
3. the generated email will appear in the Mailpit inbox.

Mailpit is used only for testing and demonstration purposes and is not part of the Mountain Hut application image.

## Stopping the deployment

To stop and remove the containers:

```bash
docker compose -f backend/docker-compose.yml down
```

The SQLite database is stored in a Docker volume, so application data is preserved when the containers are stopped or recreated.

---

## Resetting the database

To remove both the containers and the persistent database volume:

```bash
docker compose -f backend/docker-compose.yml down -v
```

Then start the deployment again:

```bash
docker compose -f backend/docker-compose.yml up -d
```

and reload the demo data:

```bash
docker compose -f backend/docker-compose.yml exec app npm run db:seed
```

---

## Updating the deployed image

To explicitly download the latest published Mountain Hut image:

```bash
docker compose -f backend/docker-compose.yml pull
```

Then recreate the containers:

```bash
docker compose -f backend/docker-compose.yml up -d
```

## Building the image locally

The published Docker Hub image is sufficient to run the application.

For development purposes, the image can also be built locally from the repository root:

```bash
docker build -t mountain-hut:latest .
```

The root `Dockerfile` uses a multi-stage build:

1. the React frontend is compiled;
2. the backend production dependencies are installed;
3. the compiled frontend is copied into the final image;
4. Express serves both the API and the frontend.

The Mountain Hut application is therefore distributed as a single application image, while Mailpit remains a separate infrastructure service managed automatically by Docker Compose.
